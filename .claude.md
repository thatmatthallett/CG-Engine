# CLAUDE.md - Development Guidelines for CG-Engine

## Project Type
Game engine framework for multiplayer 2D card games (web + mobile).

## Architecture Principles
1. **Rule Externalization**: All game rules live in JSON modules, never hardcoded
2. **State Safety**: TypeScript strict typing; no implicit `any`
3. **Event-Driven**: Turn logic as reactive handlers to state changes
4. **Zero Cost First**: Use Firebase Free Tier + Supabase Realtime

## Core Components (in order of importance)

### 1. Rule Module System (`src/rules/`)
This is the MOST IMPORTANT component. It defines how games work:
- `validMoves(state) → ActionSchema[]`: What can players do from any state?
- `turnOrderFunction`: How to compute next player (can be game-specific)
- `discardHeapRules`: Rules about taking/discarding cards
- `winCondition(schema)`: Boolean function checking if someone won

**JSON Schema Example:**
```json
{
  "gameId": "progressiveRummy",
  "validMoves": {
    "initialHandState": ["draw", "discard"],
    "discardPileHasCards": ["takeDiscard", "discard"],
    "playerCanCompleteSet": ["declareSet", "discard"]
  },
  "turnOrderFunction": "circularByPlayerIndex"
}
```

### 2. Game Session Manager (`src/game-session/`)
Handles:
- Creating/loading/saving game state
- Lobby management (waiting for players)
- Turn order tracking

### 3. Turn Engine (`src/turn-engine/`)
The core game loop:
```typescript
await turnEngine.draw(playerId);      // Draw card
await turnEngine.discard(playerId, card);  // Discard or take discard
checkWinCondition(nextState);        // Check if someone won
broadcastState(nextState);           // Sync to all clients
```

### 4. Notification Manager (`src/notifications/`)
Handles protracted play:
- AFK timeout detection
- Pass/Act notification delivery
- Decision timeout (30s default)

## TypeScript Typing Patterns

Always use these patterns for safety:

```typescript
// State object (immutable, copy on mutation):
interface GameState {
  players: PlayerState[];
  currentTurnIndex: number;
  discardPile: Card[];
  declaredSets: DeclaredSet[];
}

// Action schema (validated by RulesEngine):
type Action =
  | { type: 'draw'; playerId: string }
  | { type: 'discard'; playerId: string; card: Card }
  | { type: 'takeDiscard'; playerId: string; card: Card }
  | { type: 'declareSet'; playerId: string; cards: Card[] };

// RulesEngine.validateMove(state, action) throws if invalid
```

## Firebase Free Tier Limits (Plan Around These)
- Firestore: 50k reads/day, 1GB storage
- FCM: 50k push notifications/month
- Function invocations: 2M/day
- Web sockets: 50 concurrent connections

## File Structure Guidelines
```
src/
├── rules/           # Rule modules (JSON schemas)
│   ├── loader.ts    # Loads and validates rule sets
│   └── progressiveRummy.json  # Example game rules
├── game-session/    # Session management
│   ├── manager.ts   # Create/load/save games
│   └── lobby.ts     # Waiting room logic
├── turn-engine/     # Core game loop
│   ├── draw.ts      # Draw card logic
│   ├── discard.ts   # Discard/take rules
│   └── win-check.ts # Win condition evaluation
├── notifications/   # Protracted play handling
│   ├── afk-manager.ts  # Timeout detection
│   ├── pass-act-handler.ts    # Pass/Act decisions
│   └── push-service.ts  # FCM integration
├── state/           # State types and persistence
└── utils/           # Helpers (card math, turn order)
```
